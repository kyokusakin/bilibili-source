# bilibili-source 1.0.7

Fixes playback startup failures when a Bilibili media CDN returns HTTP 567.

- Request media from byte zero on Bilibili CDN hosts when Lavaplayer has not already set a byte range. Existing seek ranges and API requests are unchanged.
- Try Bilibili's backup CDN URLs when the primary returns an unsuccessful HTTP status at startup. This applies to progressive MP4 and the selected AAC-LC DASH stream.

The CDN behavior is documented in [yt-dlp #17847](https://github.com/yt-dlp/yt-dlp/issues/17847).

## Artifacts

- `io.github.kyokusakin:bilibili-common:1.0.7`
- `io.github.kyokusakin:bilibili-plugin:1.0.7`

## Upgrade

Update the Lavalink dependency to `io.github.kyokusakin:bilibili-plugin:1.0.7` or replace the previous plugin JAR. Restart Lavalink.
